# 视觉信息支持与重量—距离对应关系：运行说明

本轮交付第一项实验的自包含 notebook：`VisualTorque_VisualInformationSupport_GPU.ipynb`。它包含开发与独立验证两种模式；辅助代码已嵌入，不必单独上传 Python 文件。后续的内部干预与跨视觉条件预测不在这份 notebook 中运行。

## 现在怎么跑

1. 上传 notebook 到 Colab，连接可以容纳完整 BF16 模型的 GPU，并保留 Drive 中原有 `VisualTorque/toolkit` 和历史实验结果目录。
2. 保持默认 `MODEL_KEY='gemma12b'`、`PHASE='development'`、`RUN_ID='main'`，从头运行。
3. 完成自动导出后，使用全新 GPU 运行时，把 `MODEL_KEY` 改为 `'qwen27b'`，其余保持不变，从头运行。
4. 先检查这两个开发输出，确定提示、编号可读性、生成与评分的一致性、家族方差和实际运行成本。
5. 两模型开发完成后，才把 `PHASE` 改为 `'validation'`，再分别运行两模型；首次验证前决定 `N_VALIDATION=96` 或 `128`。首次验证生成清单后不能以同一 RUN_ID 改数量。若修改实验协议或代码，使用新 RUN_ID 并重新完成开发。

不需要重跑旧的 readout、calibration、format-transfer notebook，也不需要运行 Qwen-9B。Gemma 需要已获授权的模型访问和 Colab Secret `HF_TOKEN`；令牌不写入实验输出。Qwen-27B 沿用原全量 BF16，建议使用 96 GB 级别或能够完整容纳权重的 GPU；单张较小显存卡可能不足，代码不会用量化或 CPU 卸载替代本设置。

## 这轮在比较什么

五个主要输入条件：

| 条件 | 输入 |
|---|---|
| image | 编号场景图，侧别和编号字段，重量与距离均为 not provided |
| image_weight | 相同图像与字段，提供各堆真实重量 |
| image_distance | 相同图像与字段，提供各堆真实距离 |
| image_full | 相同图像与字段，提供每堆对应的重量和距离 |
| text_full | 与 image_full 相同的文字，但不发送图像 |

另有 `legacy_image`：无编号的原风格图像和旧内容实验的提示，用作协议衔接参照。它同时改变编号、信息表和提示，不能解释为只改变编号的单因素实验；新条件与旧条件也都提供相同的通用力矩规则。

输入中不提供场景的局部力矩、左右力矩总和、净力矩或正确答案。编号是随机分配到物理位置的 S1–S4，不按重量排序；同一家族的对应关系交换与镜像保持编号身份。主要图像条件使用完全相同的图像文件和信息表结构；数字与 `not provided` 的实际 token 长度可能不同，输出会记录而不宣称严格等长。

本轮是四堆积木场景，每侧两堆，重量和距离均在 1–6 的范围内，沿用已有画布和刻度。图像＋距离的结果反映显式空间信息支持，不单独定位视觉编码器错误。纯文字提供的是真值输入，不是无真值的新方法，也不是模型能力的严格上界。

## 场景与规模

| 类型 | 开发家族 | 默认验证家族 | 含义 |
|---|---:|---:|---|
| congruent | 4 | 12 | 重量、距离总和与真实力矩方向一致 |
| balanced | 4 | 12 | 精确物理平衡，避免只保留左右倾斜任务 |
| equal_weight_distance | 8 | 24 | 左右重量多重集合相同，同一重量在两侧的距离差方向一致 |
| weight_conflict | 8 | 24 | 总重量规则与真实倾斜方向相反 |
| binding_swap | 8 | 24 | 交换同侧两个位置的重量，左右各自的重量与距离集合不变，但正确倾斜方向反转 |

普通家族包含原图和镜像；交换家族包含交换前后两图及其镜像。每张图使用三种循环 ABC 映射，让每个真实答案均占据三个符号位置。所有条件与两个模型共享每一阶段的家族。

- 开发 32 家族：80 张场景呈现 × 6 条件 × 3 映射 = **1,440 次评分前向/模型**。
- 验证 96 家族：**4,320 次评分前向/模型**。
- 验证 128 家族：**5,760 次评分前向/模型**。
- 每个阶段另有 **60 次短答案生成检查/模型**，最多生成 16 个 token。

这些是计算次数，不是 GPU 耗时承诺。验证样本数是预算起点，不能当作功效保证；开发集可用于评估精度与成本，验证集结果不能用于挑选条件、修改编号或增加样本。

统计单位是物理家族，先平均家族内部的镜像、映射和配对成员。总体正确率对家族等权，交换家族不会因多一张原场景而获得双倍权重。交换子集主要报告同一镜像、同一映射下“两张都正确”的比例，单纯改变答案不算通过。

## 正常生成与候选评分

沿用固定 checkpoint 和 Transformers 5.14.0、单输入 BF16 前向、关闭 thinking 的直接回答协议；Pillow 固定为 11.3.0 以稳定新增编号图像。候选标签必须能在共同前缀后单 token 评分。

每类场景预先按家族标识选择两家族，取未镜像的 base 图、一种固定映射、全部六条件，另运行正常贪心生成。分别记录严格输出 A/B/C 的比例、有效输出中的一致率和全部检查中的一致率，保留不符合格式的输出。评分与生成存在差异时据实报告，不自动改评分协议、不筛掉这些输入，也不把候选评分准确率等同于所有自由推理条件下的能力。

这份 notebook 不保存隐藏状态；后续干预需要在对应运行环境重新采集并校验。保留的物理场景、编号、映射、图像、提示、模型与处理器身份、输入 token 和张量校验值可用于确定相同输入。来源—接收组合仍需满足后续内容干预自身的构造约束，不能把所有行为家族直接当作现成干预对。

## 七项预设比较

每个模型比较：重量支持、距离支持、完整支持相对图像基线的总体正确率变化；完整支持的四条件交互；等重场景的距离支持；重量冲突场景的完整支持；交换家族的双图全对率变化。

交互为 `image_full − image_weight − image_distance + image`，只说明该输入对照下的非加性变化，不直接证明定位了变量绑定机制。

验证使用家族配对 bootstrap 95% 区间与双侧符号翻转检验；非零家族差值不超过 16 个时使用精确符号枚举，否则 10,000 次随机翻转。两个模型合并对 14 项主比较做 Holm 校正。开发结果只用于描述和方案选择；一个模型完成时只显示模型内校正，最终跨模型比较待两者完成。

纯文字和旧协议参照、其他题型分组、分数差、错误跟随重量规则及修复/新增错误计数作为描述性结果完整保留。这里“修复”是改变输入信息后的错误纠正，不是隐藏状态干预。修复率与损害率分别保留原错误、原正确分母；分母为零时留空，不填 100%。

## 历史排重和断点续跑

代码读取 `data/*/scenes.jsonl`、旧实验目录及其指定运行中的 `support.json`、`historical_geometry_snapshot.json` 等明确清单，不遍历激活分片。第一次保存 `historical_exclusion.json`，以后核对并复用；验证还会排除开发几何及镜像。

若历史结果只存在于 ZIP 或非标准位置，把包含几何的清单文件解压后填写 `EXTRA_HISTORY_FILES`，再开始新 RUN_ID。缺少历史材料时会给出说明，不悄悄假定没有重复。排重范围以输出中的文件清单为准，不声称覆盖没有导入的实验。

同一阶段、同一模型可以从头运行以续跑，完成的输入会核验后跳过。每六条评分及异常退出时写入已完成记录；若整个运行时被强制销毁，最多需要重算最近未同步的几条。更换影响结果的版本、处理器、GPU 类型或配置会被识别，不混入旧结果。

最后一格可以在前面的配置与辅助函数已加载后单独运行，导出部分结果；部分结果明确标为 `partial_not_complete`。没有完成全部计划输入时，不计算正式完整结果。
