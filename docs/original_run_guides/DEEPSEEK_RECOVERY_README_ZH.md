```text

                 'Insufficient unused geometries; do not silently change task ranges')
```

原程序要求 64 个独立家族，四个类别各 16 个。历史几何排除后，等重量、不同力臂类别只找到 13 个；错误发生在确认集生成时、模型确认前向之前。开发阶段已完成并冻结候选。GPU 环境在附件中通过检查，本次报错不是 CUDA 或显存问题。

## 运行方法

1. 上传 `03_DeepSeek_Repair_4_5_fixed.ipynb` 到 Colab。从第一格依次运行；代码已内嵌，无需上传其他文件。
2. 保持原 `PROJECT_ROOT` 和 `RUN_ID='blackwell_cu128'`，不删除旧结果，不必重跑 notebook 01/02。
3. 已有 `selected_route.json` 和对应方向文件时，开发单元验证并复用，不重新选层或剂量。
4. 确认单元先检查四类几何容量，再冻结样本数修订。确认阶段中断时，用本恢复版、同一个 RUN_ID 重跑即可续跑。
5. 最后一格打包所有已有结果，包括新确认目录。即使中断，也可以先导出。

## 这是明确的样本数修订

恢复版采用 **52 个独立家族，四类各 13 个**。每个家族有镜像、渲染、映射组合形成的 8 个展示，35 种条件：416 个展示、14,560 条条件记录。统计独立单位仍是物理家族。

这个选择依据附件报告的几何容量，发生在确认结果出现之前。它保留原重量/力臂范围和四类均衡，继续排除历史用过的几何及其镜像；不解除排重、不拓宽任务范围、不依据效果重抽样。如果其他类别也不足 13 个，程序会停止，不再自动缩减样本。

由于样本数从 64 减为 52，统计精度会降低。将来入稿必须披露这项修订，不能把它写成原计划 64 家族的确认。若必须保留 64 个家族，需另行制定扩大几何域或修改历史复用规则的实验方案，不能直接移除当前断言。
