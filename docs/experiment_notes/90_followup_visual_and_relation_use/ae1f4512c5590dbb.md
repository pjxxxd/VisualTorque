# VisualTorque：物理关系使用诊断 — Gemma-12B

这本 notebook 同时测试：去掉字母选项、分阶段提供正确中间结果，以及明确列出简短计算。
已预设 `gemma12b`，不需要改成其他模型。两模型必须分别使用干净的 GPU runtime。

**按顺序从头运行即可。** 开发与验证场景在模型运行前一起生成并冻结；同一本中先跑 24 个开发家族，再跑 96 个独立验证家族。
开发阶段用于检查生成与测量，不自动搜索最佳提示或删除失败场景。

- 同一物理场景比较图片、正确重量与距离、正确局部力矩、正确两侧总力矩。
- 每级包含 3 种 A/B/C 映射和直接语义回答；完整变量另含显式计算。
- 有翻转答案的交换题、答案不变的交换题、镜像、重量冲突、等重距离、平衡题。
- 独立组件问答不传入主任务。完整生成及结束标记决定评分，不使用首字母候选分数。
- 每模型计划 7,960 次生成（开发 1,592；验证 6,368），不是 7,960 个独立场景。
- Gemma 建议 A100 40 GB；Qwen 建议 80/96 GB。完整 BF16，不自动量化或 offload。

需要已有 Drive 项目中的 toolkit。历史排除默认读取之前 Frozen_Visual_Validation 的原目录，或两模型任意一份结果 ZIP。
两模型的历史场景相同，因此不需要分别准备两个来源 ZIP。不会递归扫描整个 Drive，也不需要新的 calibration。
可以设置 `EXTRA_HISTORY_FILES` 增加其他已完成实验的场景清单；独立性只覆盖实际读取的清单。

已完成区块会复用；同一 runtime 内逐回答本地保存，Drive 每个场景保存一次。runtime 被删除时最多重做当前场景的 19 个回答。
输出位于 `results/relation_use_v1/main/`。最后一格可以导出部分结果；不要把部分结果当作完成验证。
