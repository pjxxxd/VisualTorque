# 左右方向与平衡选项：小规模协议诊断

**先跑默认 Qwen-27B；完成后换全新 GPU 运行时，仅把 `MODEL_KEY` 改为 `gemma12b`，从头运行。**

上一轮发现 Qwen 偏向回答左侧，两模型对四个真正平衡家族均答错。本 notebook 用简单场景检查这些现象是否也出现在容易判断的正例上，并复跑一小部分旧输入。

- 8 个刻意构造的简单家族：重量导致左右倾斜、等重但距离不同、左右完全对称、不同重量与距离恰好抵消。每个家族包含镜像，使用三种循环 ABC 映射。
- 4 种输入：旧图像提示、当前编号图像、图像＋完整变量、纯文字完整变量。
- 3 种表达：原文；只把 equal 换成 balanced (neither side tips)；在此基础上只把问题改成 What happens to the balance scale?。不依据结果自动挑选最优提示。
- 24 个原样复跑输入来自上一轮四个平衡家族，保留原图、原提示、原映射；如数值有漂移，完整报告，不因任意分数阈值停止导出。

每个模型 **600 次评分＋120 次短答案生成检查**。这是描述性诊断，不是独立验证；不把镜像和映射重复算作独立样本。没有层扫描、训练或内部干预，也不更改原实验。

需要 Drive 中原有 toolkit 和上一轮两个 development 输出 ZIP；默认从原结果目录读取，没有递归扫描。若 ZIP 不在原位置，在配置中填写 `SOURCE_ZIPS` 的确切路径。辅助代码已嵌入，只需上传这个 notebook。

模型、revision、Transformers 5.14.0、Pillow 11.3.0、BF16、batch=1 和关闭 thinking 的设置沿用上一轮。Qwen-27B 建议使用上次成功的 96 GB 级别 GPU；代码不切换量化或 CPU 卸载。Gemma 仍需相应模型访问权限。

新输出写入 `results/direction_balance_diagnostic_v1/main`。可从头续跑，最后一格也可以导出部分结果。先看两模型的诊断 ZIP，再决定验证协议；本 notebook 不会启动 validation。
