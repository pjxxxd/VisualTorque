# 视觉信息支持与重量—距离对应关系

**先跑开发：默认 Gemma-12B，`PHASE='development'`；完成后用全新 GPU 运行时改为 Qwen-27B，再从头运行。**

这份 notebook 是下一轮的第一项实验：比较图像、重量支持、距离支持、完整变量支持和纯文字；另外保留旧图像协议作参照。它还比较重量—距离对应关系交换前后的成对场景。此处不执行内部干预，不重跑上一轮实验。

每个模型开发阶段：32 个物理家族、80 张场景呈现、6 种输入条件、3 种答案映射，共 **1,440 次评分前向＋60 次短答案生成检查**。家族共享于两模型；重复渲染、镜像和映射不算独立样本。真正平衡的场景作为小规模对照保留。所有条件都提供同一物理规则，只改变场景变量是否明确给出。

两模型开发完成后，先检查图像可读性、生成与评分一致性及家族间差异，再决定验证规模；随后把 `PHASE` 改为 `validation`。96 家族对应每模型 4,320 次评分前向；128 家族对应 5,760 次，均另有 60 次生成检查。验证集与开发集、已索引历史几何及其镜像分离；规模必须在首次验证前确定，不能看验证结果后追加。

需要 Drive 中已有的 `VisualTorque/toolkit` 和旧实验的 support / historical_geometry_snapshot / scenes 文件。辅助代码已嵌入，无需单独上传 `.py`。Gemma 需要对应 Hugging Face 模型访问权限；Qwen-27B 沿用原全量 BF16，建议使用 96 GB 级别或能完整容纳权重的 GPU，不使用量化替代。

从头顺序运行，已完成输入会核验后复用。断点记录写入独立的新目录，不覆盖旧实验。历史检查只读取指定层级的清单与快照，不递归遍历 Drive；未包含在这些清单中的 ZIP 不会自动纳入排重。

输出包括原始候选分数、完整提示、图像、对应关系配对结果、正常直接生成与评分的一致性、家族统计和文件校验清单。统计中的“修复”指输入条件改善答案，与论文中的隐藏状态修复分开解释。辅助变量含真值，是诊断条件，不是无需真值的新算法或严格性能上界。
