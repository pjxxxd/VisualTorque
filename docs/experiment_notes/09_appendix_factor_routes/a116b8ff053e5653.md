# VisualTorque — Task, Token, and Component Routing on one A100

The confirmatory experiment established a shared three-stage route in Qwen:

**image tokens → distributed prompt/options → output-adjacent chat tokens.**

This notebook asks whether that route is a torque computation or a generic
multiple-choice pathway, and which update type carries each handoff. It has three
frozen phases on 64 pairs sampled from the confirmatory manifest:

1. **Latent-query controls.** The same source/target images are queried about left and
   right units, single-stack distances, left and right torque, net torque, and final
   outcome. Source and target always receive an identical pair-specific prompt and
   identical A/B/C options.
2. **Individual-token scan.** Every option token and separator/chat token is patched
   separately at the confirmed middle and late layers, using both the matched source
   and an unrelated same-outcome donor.
3. **Component decomposition.** At frozen handoff layers, source attention updates and
   MLP updates are separately patched at option and separator/chat token groups.

The run is exploratory after the confirmatory analysis, but every pair, task, layer,
token group, control, and comparison is locked before model loading. This notebook
does not search individual attention heads; it determines whether the next search
should target attention routing, MLP transformation, or a generic answer-selection
scaffold.
