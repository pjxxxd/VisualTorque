# VisualTorque — Routing Robustness and Multiplicity Audit

This notebook audits the completed Qwen task/token/component routing experiment
**without loading the model or running any new interventions**. It reads the frozen
42,148-record result table and asks whether the exploratory signals are strong enough
to justify a targeted mechanistic follow-up.

The audit is deliberately stricter than the discovery notebook:

1. Test `changed − unchanged` latent relevance while blocking by edit type.
2. Correct token and component families with Benjamini–Hochberg FDR and a paired
   sign-flip max-T family-wise test.
3. Separate successful computation (`both_correct`) from error/decision routing.
4. Audit the previously selected candidate across deterministic halves and edit types.
5. Route the next experiment through a frozen decision gate. Because the selected
   Qwen layer is `linear_attn`, standard full-attention head patching is not assumed.

All audit outputs are written to a new `robustness_audit_v1` directory. Original
captures and analyses are read-only.

## 2. Frozen statistical utilities

Bootstrap intervals resample pairs. Paired donor/component contrasts use the same

## 3. Competence and latent relevance

Recovery of a model's source logits is meaningful even when the model is wrong, but
it describes a decision pathway rather than a successful physical computation. The
competence audit therefore precedes mechanistic interpretation.
