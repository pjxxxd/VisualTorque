# VisualTorque — Confirmatory Counterfactual Causal Tracing on one A100

This notebook confirms the pilot's central mechanistic observation with a larger,
balanced, frozen sample. The pilot suggested a three-stage route:

**image tokens (early) → distributed prompt/text tokens (middle) → final answer
token (late).**

The confirmatory design makes four corrections before any component-level circuit
claim:

1. increase from 8 to 32 pairs per edit family (128 total);
2. sample densely around layers 12–18 and 22–28;
3. apply unrelated-donor controls to image, all-text, and final-token scopes;
4. split the text residual stream into intro, rule, question, options, answer
   instruction, and chat-special tokens.

`add_unit`, `move_stack`, and `mirror` use outcome-changing pairs.
`redecompose` preserves net torque and outcome. Layer 31 is retained only as an
implementation ceiling and is excluded from mechanistic evidence. All confirmatory
hypotheses, pair sampling, controls, and statistics are locked before model loading.

This notebook is intentionally Qwen-only. A cross-model Gemma run should use the
frozen conclusions and model-relative layers after Qwen confirmation, rather than
copying Qwen's absolute layer numbers prematurely.

## 3. Batched natural activation patching and token segmentation

Conditions for the same target image are scored together in batches of up to four.
An automatic fallback halves a condition batch after a CUDA out-of-memory error. Text
segmentation is verified against tokenizer offsets and must partition every non-image,
non-final token exactly once.
