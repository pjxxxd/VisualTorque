# VisualTorque — Targeted Shortcut-Error Rescue and Induction

This experiment tests whether model-specific internal routes explain specific physics errors rather than trying to predict every error with one score. It studies two predeclared cases: the exact torque answer conflicts with a weight-only shortcut, and the exact answer conflicts with a distance-only shortcut.

Each independent family contains four scenes with the same correct outcome. The base scene contains the shortcut conflict. A factor-aligned source changes only the implicated factor so that its cue agrees with exact torque; a factor-amplified source strengthens the incorrect cue while exact torque still predicts the original answer; an irrelevant-factor source changes only the other factor. Because every source has the same physical answer as the base, a targeted shortcut error after intervention cannot be explained by copying the donor's answer.

The primary site is the previously frozen factor-composition site; the late answer site is secondary. Rescue is tested only among base scenes answered with the specified shortcut. Induction is tested only among base scenes initially answered with exact torque. Self replay, norm-matched wrong-factor edits, and norm-matched random edits are mandatory controls. Run the unchanged notebook in fresh A100 runtimes for `qwen27b`, `qwen9b`, and `gemma12b`.
