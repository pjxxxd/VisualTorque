# VisualTorque — Qwen-27B Net-Torque-to-Answer Fracture Rescue

The preceding 900-scene audit found a large and unusually clean error class:
Qwen-27B often gave the wrong tipping outcome even when the signed net torque
was both recoverable from the outcome-prompt hidden state and answered
correctly in a separate net-torque question.  This notebook turns that
diagnostic association into a frozen causal test.

Before loading the model, it freezes binary left/right errors whose net-torque
sign is correct in both the direct task and the held-out readout.  It does not
condition this primary cohort on the previous, overly strict requirement that
both side-torque magnitudes be exactly correct.  None of the new intervention
outputs are used for target selection.

The intervention ladder has three functionally ordered sites:

1. **L32 net-torque axis:** amplify the already-correct signed net-torque
   component learned only from `probe_train + probe_dev` outcome states;
2. **L49 physical-side semantic:** add an independently learned left-versus-
   right semantic direction;
3. **L55 answer code:** add the code transition required by the target prompt's
   current A/B/C mapping.

Every target is tested under two mappings that swap the labels assigned to the
correct and erroneous physical sides.  Equal-norm random, reversed-physics,
and stale-mapping controls are mandatory.  If L32 amplification fails while
L49 semantic steering rescues the same errors across both mappings, the
predeclared interpretation is a net-torque-to-semantic handoff fracture—not
absence of net-torque information and not simple option-letter copying.
