# VisualTorque — Qwen3.5-27B Metric-vs-Ordinal Boundary Audit

前一个冻结实验发现：LoRA 大幅改善距离相关 outcome，并压低重量捷径；但绝对距离准确率没有提高、显式 net torque 反而下降，而且 near-boundary 场景显著失败。

本 notebook 在任何模型推理前冻结一套新的、SFT 不可见的检验，用来区分三种行为解释：

1. **Exact metric route**：模型读取绝对距离，计算左右 torque，并在很小的 torque 差上仍然正确。
2. **Coarse magnitude-sensitive route**：模型不只看“谁更重/谁更远”，也能感知大致幅度，但无法处理精确边界。
3. **Ordinal replacement shortcut**：模型主要依赖“谁更重、谁更远”等顺序关系；当顺序关系相同但正确 outcome 相反时不能同时答对。

测试包含两个完全隔离的 track：

- **In-range SFT-unseen**：44 个 Dataset v1 `probe_test` single-stack 场景，全部不在 LoRA SFT 中。
- **Distance extrapolation**：44 个全新场景，至少一侧距离为 7–10；Dataset v1 的最大距离必须为 6。

每个 track 包含：

- 12 对 ordinal-matched outcome-flip 场景：每一对“更重的一侧”和“更远的一侧”完全相同，但一个由重量侧获胜、另一个由距离侧获胜；
- 12 个 `|net torque| ∈ {1, 2}` 的 near-boundary 场景；
- 8 个 unequal-factor、exact-balance 场景。

模型分别回答绝对距离、距离关系、左右 torque、net torque、torque 关系和最终 outcome。所有关键 A/B/C 问题都做三种平衡排列，并加入 symbolic 对照。该实验只能提供**行为路由特征**，不会单独宣称内部机制。
