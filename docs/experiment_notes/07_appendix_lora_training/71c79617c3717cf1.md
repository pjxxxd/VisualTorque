# VisualTorque：方向交叉与剂量实验的 review_bundle 分析（CPU v1）

直接读取 Drive 中上一轮生成的 `review_bundle.zip`，无需 GPU、Torch、模型、adapter，也不重新推理。Colab 选择普通 CPU 会话，按顺序 Run all；默认寻找：

`/content/drive/MyDrive/VisualTorque/results/qwen27b_handoff_axis_dose_crossover_newgeometry_v1/review_bundle.zip`

若文件在其他位置，只需修改第 2 阶段的 `SOURCE_ZIP_OVERRIDE`；可以选择原 ZIP，也支持压缩包外面多一层文件夹的版本。整个输入包只读，所有新输出保存在独立 CPU 分析目录。

本轮回答：

1. 新 6／7 块砝码集合的自然准确率、修复/退化、两侧与映射一致性如何？
2. 原六项主检验能否从干预明细重建？哪些变化来自目标阻断、随机阻断、自钳制或总干预响应？
3. 绝对/相对剂量、正/负剂量、Native/LoRA 注入轴与阻断轴交叉分别显示什么？
4. 上游干预到达 L49/L55 的带符号投影、绝对投影和完整状态位移如何变化？是否与 L55 直接响应呈现不同变化？
5. 这些结果在 6/7 块、左/右、答案映射、物理线索冲突类型下是否一致？

**统计口径：**独立单位为镜像等价的物理 family。先在 family 内平均重复观测，再计算模型差值或交互；不能把 17,920 次干预当成独立样本。原六项主检验按原 seed、bootstrap、sign-flip 和 Holm 规则重算并核对。其余是看过结果后的次级分析，只报告逐项 95% family-bootstrap 区间，不增加新的“显著通过”判据。6 块与 7 块来自不同 family，比较两组时分别重采样，不强行配对。

**包内容限制：**原导出器有意不打包 `frozen_crossover_axes.pt` 和 `dose_inventory.json`。本 notebook 不把它们误报为损坏：用完成清单中的轴哈希及剂量 CSV 重建身份链，并明确记录未直接验证轴张量、clean 张量、逐条件原始 logits 或原图。可以验证包内记录、计算口径和内部一致性；不能据此重新证明模型前向计算本身正确。

**解释边界：**本轮数据是扩展重量范围，不代表原分布总体准确率。方向不同不自动等于因果通路旋转；阻断损失不是自然间接效应；相关性不是机制中介证据；不显著也不等于相等。L48 始终是固定 Native 物理轴，没有 LoRA L48 轴实验。
