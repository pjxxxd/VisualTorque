# VisualTorque — Post-LoRA Style × Answer-Code Crossover Audit

**下一步：先排除画风和答案字母混杂，再决定是否继续做 L50 因果机制验证。**

上一轮 MetricRoute 的 12 对 ordinal-flip 场景中，`weight_wins` 全部采用 blue_shift，`distance_wins` 全部采用 coral_shift。两种原有画风同时改变颜色、画布、方块大小；本实验测量的是**整套画风**的影响，不能把结果单独归因于颜色。上一轮 outcome 使用 ABC、torque_relation 使用 XYZ，也把任务和答案字母绑定在一起。

本 notebook 固定既有 adapter，读取上一轮全部 44 个物理场景，让**每个场景 × 两种原有画风 × 两个任务 × 两套字母 × 原先三个 Latin 映射 × 两个模型状态**全部交叉：1,056 个输入、2,112 次主评分。保留 24 个配对场景作主要诊断，12 个 near-boundary 和 8 个 exact-balance 作边界诊断。另有少量评分自检。

- 不训练、不改权重、不拟合或重新挑选 L50 子空间；不执行大规模 patch。
- 这是**已看过场景的受控事后复核**，不是新的盲测。设计和源文件在本轮推理前锁定，仍不能称作最初的预注册确认。
- 同一物理场景在不同画风、任务和字母下沿用该任务原先选中的三种语义排列，避免换画风时同时换选项顺序。
- 把配对关系和镜像关系合并成独立 family，再计算置信区间；不把多个画风、字母、选项排列当成独立样本。
- 多数投票遇到三方平票时记作 `tie`，不按字母序强行选 balanced；另存旧规则结果以便核对旧表。
- 不把“换风格后答案保持不变”当成答对，也不把“配对发生翻转”当成物理推理成功。

**运行：**沿用上一轮已成功的 Colab / 96 GB GPU 环境，保留 Google Drive 中的完整 `VisualTorque/toolkit`、训练 adapter 和 `qwen27b_postlora_l50_metric_route_blind_causal_v1` 结果目录，按顺序 Run all。无需重新上传训练集，也无需重新训练。安装依赖使用上一轮已跑通的固定版本；若当前会话已导入其他版本的 Transformers/PEFT，请先使用新的运行会话。

**输出：**`results/qwen27b_postlora_style_code_crossover_v1/`。每个模型/输入单独保存，重连后重新 Run all 可校验并续跑。完整结束会输出 `FOLLOWUP_REPORT_ZH.md`、`audit_decision.json`、CSV、图和 `RUN_COMPLETE.json`。输出目录独立于全部前序实验。
