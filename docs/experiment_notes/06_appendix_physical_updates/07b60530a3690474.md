# VisualTorque：Native 物理更新的家族稳健性、来源预测与状态对齐（CPU v1）

**接在已完成的 Native PhysicalUpdate Confirmation v2 之后。Colab 选择 CPU，按顺序 Run all。**

文件移动过时，只需修改第 2 阶段 `SOURCE_ZIP_OVERRIDE`。读取的是原 GPU review_bundle，不是其他 AxisDose 或 CPU 汇总 ZIP。本 notebook 不依赖其他 notebook、不加载 Torch/模型、不重新推理、不修改源结果。

本轮把刚得到的正结果解释得更具体：

1. 从包内逐条件分数重新计算原四项主检验、准确率变化和冻结判断，核对原结果。
2. 效应在多少家族为正？删去任意一个家族、分开镜像与六种答案映射后怎样？
3. **来源正确答案不变时，模型自己的预测是否也不变？** 在来源预测稳定、稳定且无并列第一、稳定但错误、前后均正确等子集中，用相同配对记录比较物理更新与控制。
4. 半剂量、正向、反向响应与最终三分类准确率有什么关系？物理更新是否比 clean 更容易复制来源答案？
5. L49/L55 诱导位移是否沿真实反事实位移移动，是否优于同范数控制，是否真的更接近真实反事实状态？

**本轮为看过结果后的次级审计，不是新确认实验。** 原主检验沿用原 seed、family bootstrap、sign-flip 与四项 Holm 校正。新增分析只报告逐项描述性 family-bootstrap 区间，不新增“通过”门槛。空子集输出 NA；支持数不足时不制造置信区间。镜像、映射、来源变体和干预次数均不是新的独立样本。

来源预测稳定只控制离散 argmax，不排除置信度变化或其他混合信息。源预测标签并列第一另行记录；各子集使用自身入选家族，不能把不同支持集的均值差直接解释成效应修饰或因果机制。能力筛选不用 patch 后的结果。

**状态对齐公式：**设诱导位移为 δ，自然反事实位移为 v，包内保存 n=‖δ‖、m=‖v‖、p=δ·v/‖v‖。计算沿反事实方向的相对分量 p/m，以及相对距离 `sqrt(n²+m²−2pm)/m`。后者 clean 基线为 1，小于 1 才表示更近。m 为零时无定义，保留缺失及覆盖数；正投影不自动表示更近。只复核已保存的测量，不把对齐或相关性称为自然中介、必要性或完整电路。

包内有完整候选分数、clean 元数据、干预 shards 和 trace 标量；**没有完整 clean/干预隐藏张量**。本 notebook 核对这些记录的哈希、身份与计算一致性，不重新证明模型前向正确。v1 旧记录和 v2 精确向量核验记录分别标注，并提供所有配对条件均为 v2 的敏感性分析。
