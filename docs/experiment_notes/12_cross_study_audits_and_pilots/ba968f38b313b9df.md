# VisualTorque — Qwen3.5-35B-A3B Larger-Model Fracture Replication

This notebook asks whether the paper's central observation survives in a larger, architecturally different Qwen3.5 model: when the model gives the wrong lever outcome, are weight, distance, side-torque, or net-torque quantities nevertheless still available internally or answerable directly?

The experiment uses the same exhaustive 900-scene single-stack universe, the same deterministic answer mappings, and the same train/dev/test split as the frozen Qwen-27B audit. It first measures whether the 35B-A3B checkpoint is actually more competent on VisualTorque. It then fits model-specific linear readouts on train/dev only, freezes an error-versus-matched-correct cohort using behavior alone, and maps the first candidate point at which physical information stops agreeing with the final outcome.

This is a larger-total-parameter and cross-architecture replication, not a pure dense scaling law: Qwen3.5-35B-A3B is a sparse MoE with 35B total and 3B active parameters. A later causal intervention is authorized only if this notebook finds enough errors in a prespecified fracture class. Run on one A100 80GB. Captures are sharded and safely resume after interruption.
